    1. Контекст: ИИ ⊃ ML ⊃ DL

    из лекции

    1 Зачем

    Нужна общая карта: где DL сидит относительно классического ML, который вы уже умеете, и какой цикл повторяется в каждом семинаре.

    2 Интуиция

    3 Определение

    ИИ (artificial intelligence) — системы для задач, требующих «интеллекта». ML (machine learning) — обучение по данным без явных правил. DL (deep learning) — ML на многослойных нейросетях.

    Обучение с учителем: пары $(x, y)$, минимизируем loss. Цикл: данные → модель → предсказание → ошибка → обновление весов → тест.

    4 Вывод цикла

    Модель $a(x; w)$ даёт $\hat y$.
    Параметры $w$ — то, что учим.
    Loss $L(\hat y, y)$ измеряет ошибку; средний loss по выборке — цель минимизации.
    MSE для регрессии, CE для классификации (модуль 2).
    Градиентный шаг: $w \leftarrow w - \alpha\nabla_w L$.
    В PyTorch это backward + optimizer.step.

    5 Числовой пример

    Линейная регрессия $a=w_0+w_1x$ — уже «нейросеть» без скрытых слоёв. Логистическая регрессия — то же + сигмоида/softmax.

    данные X,y → модель w → ŷ → L → ∇L → обновить w → (повтор) → тест

    2. Тензоры PyTorch

    из семинара

    1 Зачем

    Все данные и веса — тензоры. Без уверенного shape/dtype/device следующие темы (autograd, слои) сыплются ошибками.

    2 Интуиция

    Тензор ≈ NumPy-массив + метаданные (device, requires_grad) + история операций для autograd.

    3 Определение

    Создание: torch.tensor, rand/randn/zeros/ones/randint, from_numpy (делит память!). Форма: .shape, .dim(). Преобразования: reshape, view, ravel, cat, stack, squeeze/unsqueeze. Агрегации: sum/mean(..., dim=). Копия: clone.

    x: (N, d) W: (out, in) dtype float32 по умолчанию у слоёв

    4 Вывод

    from_numpy не копирует: правка массива меняет тензор.
    Для независимости — .clone() или torch.tensor(np_arr).
    unsqueeze(0) добавляет ось батча; squeeze убирает оси длины 1.
    Часто нужно перед/после Linear.
    cat — вдоль существующей оси; stack — создаёт новую.
    (2,3)+(2,3) cat dim0 → (4,3); stack → (2,2,3).

    5 Числовой пример

    Shape после операций — введите N,d и посмотрите.

    6 Интерактив

    Калькулятор shape: reshape / unsqueeze / cat

    (1) reshape(N,-1) для (N,1,28,28); (2) unsqueeze(0) у вектора (d,); (3) cat двух (N,d) по dim=0.

    3. Грабли из семинара

    из семинара

    1 Зачем

    Три ошибки молча портят обучение: broadcasting, dtype, device. Их узнают по странному loss или сообщению об ошибке.

    2 Интуиция

    Broadcasting «дотягивает» оси; если вычитать столбец из вектора, получается матрица — и MSE считается не по тем объектам.

    3 Определение

    Broadcasting: (400,1) − (400,) → (400,400). dtype: NumPy float64 vs Linear float32 → mat1 and mat2 must have the same dtype. device: нельзя складывать CPU-тензор с CUDA-тензором.

    4 Вывод

    Выравнивание справа: (400,) → как (1,400); против (400,1) → (400,400).
    Лечится .ravel() / .view(-1) у обоих.
    x = torch.from_numpy(arr).float() или сразу dtype=torch.float32.
    Слои создают weight в float32.
    Один device: model.to(device); batch = batch.to(device).
    Иначе RuntimeError про devices.

    4. Autograd

    из семинара

    1 Зачем

    Считать производные вручную для сети из тысяч операций невозможно. Autograd строит граф и делает backward за вас.

    2 Интуиция

    Каждая операция с requires_grad=True записывает «как откатить». backward() идёт от скаляра loss к листьям и заполняет .grad.

    3 Определение

    requires_grad, вычислительный граф, grad_fn, листья (grad_fn is None), backward(), .grad, retain_grad для не-листьев. Градиенты накапливаются → zero_grad. torch.no_grad(), .item(), .detach().

    4 Вывод

    Лист — тензор, который вы создали с requires_grad; промежуточные имеют grad_fn.
    По умолчанию .grad только у листьев.
    Повторный backward без zero_grad прибавляет к старому .grad.
    Иначе шаг оптимизатора по «сумме батчей».
    Обновление весов — не часть модели → внутри no_grad (или через optimizer).
    Иначе in-place на leaf запрещён / граф раздувается.

    5 Числовой пример

    $L = (ax+b)^2$ при a=2, x=3, b=1 → L=49; ∂L/∂a = 2(ax+b)·x = 42.

    6 Интерактив

    Накопление градиентов

    (1) Нажмите «backward» дважды без zero — grad удвоится; (2) zero_grad — сброс; (3) сравните с аналитикой.

    7 Код

    import torch
w = torch.tensor([1., 2.], requires_grad=True)
x = torch.tensor([3., 4.])
loss = (w * x).sum()
loss.backward()
print(w.grad)  # [3, 4]
w.grad.zero_()
# обновление:
with torch.no_grad():
    w -= 0.1 * w.grad  # после следующего backward
    # .item() — скаляр в Python float (для логов)
# .detach() — отцепить от графа перед numpy()

    ∂/∂w₀ от (w·x) при x=(3,4) равна?

    8 Грабли

    • Забыли zero_grad → градиенты суммируются.
    • In-place на leaf вне no_grad.

    9 Где в жизни

    • Любой кастомный loss в PyTorch — тот же backward.

    10 Проверка

    Зачем zero_grad?
    Своими словами: что такое лист графа?

    Тензор-источник с requires_grad, не полученный из других операций; именно у него обычно лежит .grad.

    11 Шпаргалка

    requires_grad → граф → backward → .grad. Накопление → zero_grad. Обновление в no_grad / optimizer.

    5. Градиентный спуск

    из лекции из семинара

    1 Зачем

    Формула обучения: сдвиг против градиента. Без понимания α, батча и масштаба признаков не настроить lr.

    2 Интуиция

    Полный GD — по всей выборке; SGD — по одному объекту/мини-батчу (шумнее, дешевле). Признаки разного масштаба → разные масштабы градиентов → крошечный шаг (семинар).

    3 Определение

    $$w_{new}=w_{old}-\alpha\nabla L$$

    Батч — подвыборка; итерация — один шаг; эпоха — проход по всем данным.

    4 Вывод

    Линейное приближение гарантирует уменьшение L при малом α.
    Большой α → расходимость / NaN.
    Разный масштаб признаков ⇒ разный ‖∂L/∂w_i‖ ⇒ один α мал для всех.
    Нормализуйте признаки (модуль 0) или берите Adam.

    5 Числовой пример

    $L=w^2$, w=3, α=0.1 → w'=2.4

    6 Интерактив

    1D GD на L=w²

    (1) α=0.1 — сходится; (2) α=1.1 — расходится; (3) α=1 — осцилляция ±.

    7 Код

    with torch.no_grad():
    weight -= lr * weight.grad
weight.grad.zero_()

    Один шаг: w=3, L=w², α=0.1 → ?

    8 Грабли

    • lr слишком большой на ненормированных признаках.

    9 Где в жизни

    • Даже в sklearn SGDClassifier — тот же принцип.

    10 Проверка

    Эпоха — это
    Своими словами: батч vs эпоха

    Батч — порция для одного градиентного шага; эпоха — когда все объекты хотя бы раз попали в батчи.

    11 Шпаргалка

    w ← w−α∇L. Батч / итерация / эпоха. Масштаб признаков ↔ размер α.

    6. Нейрон и слой

    из лекции

    1 Зачем

    Линейный слой — базовый кирпич; от него идут MLP, CNN-головы, трансформерные FFN.

    2 Интуиция

    Один нейрон = скалярное произведение + bias. Слой = несколько нейронов = матрица.

    3 Определение

    $$a(x)=w_0+w_1x_1+\ldots+w_n x_n=\mathbf{w}\cdot\mathbf{x}+b$$

    nn.Linear(in, out): weight.shape = (out, in), forward x @ W.T + b.

    x: (N, in) W: (out, in) y: (N, out)

    4 Вывод

    i-я строка W — веса i-го нейрона.
    Поэтому удобно (out, in).
    Параметров: out·in + out (bias).
    Не зависит от размера батча N.

    5 Числовой пример

    Из материалов: w=(0.5,1,0.4), b=0.1, x=(0,2,1) → 2.5

    0.5·0 + 1·2 + 0.4·1 + 0.1 = 2.5; после ReLU — 2.5

    • Перепутать (in,out) и (out,in) при ручном matmul.

    9 Где в жизни

    • «Голова» классификатора поверх эмбеддингов — Linear(d, n_classes).

    10 Проверка

    weight у Linear(in,out) имеет shape
    Своими словами: что такое слой?

    Набор нейронов с общей входной размерностью; математически — аффинное отображение R^in → R^out.

    11 Шпаргалка

    a=w·x+b. Linear: W:(out,in), y=x@W.T+b. #params=out·in(+out).

    7. Зачем нелинейность

    из лекции

    1 Зачем

    Без активаций любая глубина схлопывается в один Linear — сеть не выразительнее логрега.

    2 Интуиция

    Активация «ломает» прямую: после неё композиция уже не линейна, можно строить кривые границы (XOR-подобные данные).

    3 Определение

    $$k(kx+b)+b=k^2x+kb+b\quad\text{(снова прямая)}$$ $$y=xW_1W_2W_3=xW$$

    ReLU: $\max(0,x)$, Sigmoid: $1/(1+e^{-x})$, Tanh, GELU.

    4 Вывод

    Композиция аффинных карт аффинна ⇒ глубина без σ бесполезна.
    Лекция I.
    Вставляем σ между слоями: $W_2\sigma(W_1x+b_1)+b_2$ — уже нелинейная модель.
    Отсюда MLP.
    Производная ReLU: 1 при x>0, иначе 0 (в нуле обычно 0).
    «Мёртвые» нейроны, если всегда ≤0.

    5 Числовой пример

    ReLU(-1)=0, ReLU(2.5)=2.5; σ(0)=0.5; tanh(0)=0

    6 Интерактив

    Линейная vs ReLU-сеть на «двух лунах»

    (1) Выключите ReLU — граница почти прямая, accuracy низкая; (2) включите — граница изгибается; (3) подвигайте lr/шаги.

    7 Код

  nn.Linear(2, 16),
  nn.ReLU(),
  nn.Linear(16, 1)
)

    Чему равно ReLU(-3)?

    8 Грабли

    • Стек Linear без активаций «для глубины» — самообман.

    9 Где в жизни

    • Нелинейные зависимости в транзакциях (пороги, взаимодействия) — без активаций не поймать.

    10 Проверка

    Три Linear подряд без активаций эквивалентны
    Своими словами: роль активации

    Вносит нелинейность между линейными картами, расширяя класс представимых функций.

    11 Шпаргалка

    Без σ глубина = одна матрица. ReLU=max(0,x). Активация между Linear обязательна для выразительности.

    8. Backpropagation

    из лекции

    1 Зачем

    Autograd внутри делает цепное правило на графе. Чтобы отлаживать и понимать, нужно один раз пройти пример руками.

    2 Интуиция

    Прямой проход считает значения узлов и запоминает их. Обратный — несёт ∂L/∂узел, умножая локальные производные.

    3 Определение

    Пример из лекции: $y = x_1^2 + 3(x_2 x_3 - x_1^2)$ при $x=(1,2,3)$.

    $$z_1=x_1^2,\ z_2=x_2x_3,\ z_3=z_2-z_1,\ z_4=3z_3,\ y=z_1+z_4$$

    Прямой: $z_1=1,z_2=6,z_3=5,z_4=15,y=16$. Градиенты по входу: $(-4, 9, 6)$.

    4 Вывод по шагам

    ∂y/∂z4=1, ∂y/∂z1=1 (y=z1+z4).
    Сумма: градиент копируется на оба входа.
    z4=3 z3 ⇒ ∂y/∂z3 = ∂y/∂z4 · 3 = 3.
    Локальная производная × входящий grad.
    z3=z2−z1 ⇒ ∂y/∂z2=3, ∂y/∂z1 += 3·(−1) → итог по z1: 1−3=−2 (через оба пути).
    На прямом проходе z1 входит в y дважды: напрямую и через z3.
    z2=x2 x3 ⇒ ∂y/∂x2=3·x3=9, ∂y/∂x3=3·x2=6.
    Произведение: grad×другой множитель.
    z1=x1² ⇒ ∂y/∂x1 = (∂y/∂z1_total)·2 x1. С учётом обоих путей: y=3 x2 x3 − 2 x1² ⇒ ∂/∂x1=−4 x1=−4.
    Сверка: (−4, 9, 6).

    9. Цикл обучения

    из семинара

    1 Зачем

    Это «ритуал» PyTorch: одна ошибка в порядке шагов ломает обучение.

    2 Интуиция

    Сначала посчитали ошибку и градиенты, потом сдвинули веса, потом обнулили градиенты (или обнулили до backward — главное, не смешивать батчи).

    3 Определение

    Порядок: zero_grad → forward → loss → backward → step. Модель: nn.Module с __init__ и forward; или nn.Sequential.

    4 Вывод

    Вручную: weight -= lr * weight.grad в no_grad.
    Потом заменяем на optimizer.
    optimizer.step() делает тот же сдвиг по всем parameters().
    zero_grad — метод оптимизатора или модели.
    Класс Module регистрирует параметры в __init__ через nn.Linear и т.п.
    Иначе optimizer их не увидит.

    MSELoss на pred=ŷ, target=y: mean((ŷ−y)²). Один шаг SGD уменьшает loss, если lr мал и градиент верный.

    10. Оптимизаторы

    из семинара

    1 Зачем

    На овраге plain SGD прыгает поперёк. Momentum, RMSProp, Adam меняют правило шага — часто быстрее сходятся.

    2 Интуиция

    Momentum — «инерция». RMSProp — делит шаг на типичный размер градиента параметра. Adam — оба + bias correction. AdamW — weight decay отдельно.

    3 Определение

    $$\text{SGD: }\theta\leftarrow\theta-\eta g$$ $$v=\mu v+g,\ \theta\leftarrow\theta-\eta v\quad(\text{momentum})$$ $$s=\beta s+(1-\beta)g^2,\ \theta\leftarrow\theta-\eta g/(\sqrt{s}+\varepsilon)\quad(\text{RMSProp})$$ $$m=\beta_1 m+(1-\beta_1)g,\ v=\beta_2 v+(1-\beta_2)g^2,\ \hat m,\hat v\text{ — bias corr.}\quad(\text{Adam})$$

    4 Вывод

    В овраге ∇ почти поперёк: SGD осциллирует, вдоль минимума ползёт.
    Momentum сглаживает осцилляции.
    RMSProp/Adam нормируют шаг → признаки разного масштаба перестают диктовать крошечный lr.
    Связь с семинаром про масштаб.
    AdamW: decay $\lambda\theta$ вне адаптивной нормировки.
    Стандарт для трансформеров.

    5 Числовой пример

    Овраг $f(x,y)=x^2+25 y^2$. Старт (−4, 1). Сравните длину пути визуально на виджете.

    11. Сиды и CPU / GPU

    сверх курса

    1 Зачем

    Без сидов эксперименты не воспроизводятся. Без понимания device легко словить ошибки или не использовать ускорение.

    2 Интуиция

    Сид фиксирует ГПСЧ. GPU быстрее на больших matmul, но перенос маленьких тензоров туда-сюда съедает выигрыш.

    3 Определение

    torch.manual_seed(0)
# np.random.seed(0); random.seed(0)
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model.to(device); x = x.to(device)

    4 Вывод

    Одинаковый сид + одинаковый код ⇒ те же начальные веса (на том же device/бэкенде).
    На GPU возможны недетерминизмы некоторых операций.
    Сравнивать CPU vs GPU имеет смысл на достаточно больших матрицах / батчах.
    Иначе доминирует overhead.

    5 Числовой пример

    torch.manual_seed(0); torch.randn(2) дважды в новых процессах с тем же сидом → одинаковые числа (CPU).
