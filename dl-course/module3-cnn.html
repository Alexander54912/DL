    1. Почему полносвязный слой плох для картинок

    из лекции

    1 Зачем

    Linear на пикселях ломает соседство и взрывает число параметров — свёртка решает обе проблемы.

    2 Интуиция

    3 Определение

    FC к каждому пикселю независимо от позиции. Соседство (edge/texture) не закодировано. Для RGB 224×224 → Linear(150528, 1000) уже ~1.5·10⁸ весов только в первом слое.

    4 Вывод

    Локальные паттерны повторяются по кадру → одни и те же веса можно «скользить» (свёртка).
    Weight sharing.
    Параметров у Conv ≪ FC при той же выразительности для изображений.
    Мотивация CNN.

    5 Числовой пример

    CIFAR 32×32×3 → Flatten 3072. Linear(3072,64): 3072·64+64=196672. Conv2d(3,64,3,pad=1): (9·3+1)·64=1792.

    FC params vs Conv

    7 Код

    # плохо для фото:
# nn.Flatten(); nn.Linear(3*224*224, 1000)

    Conv2d(3,64,3) params с bias?

    8 Грабли

    • Flatten до первого слоя на больших фото → OOM / overfit.

    9 Где в жизни

    • Документы/чеки/карточки в банке — почти всегда CNN/ViT, не голый MLP.

    10 Проверка

    Главный минус FC на картинках
    Своими словами

    Пиксели связаны локально; свёртка использует это через общие веса окна.

    11 Шпаргалка

    FC рвёт сетку и раздувает params. Conv = локальность + sharing.

    2. Изображение как тензор

    из семинара

    1 Зачем

    Путаница (H,W,C) vs (C,H,W) — частая причина shape errors в Conv2d.

    2 Интуиция

    PIL/NumPy часто каналы последними; PyTorch Conv — каналы сразу после батча.

    3 Определение

    PIL/NumPy: (H,W,C) PyTorch: (N,C,H,W) ToTensor: [0,1], затем Normalize

    x.permute(2,0,1) для одного кадра HWC→CHW.

    4 Вывод

    ToTensor делает CHW float; Normalize — mean/std датасета или ImageNet.
    CIFAR/ImageNet — свои константы.
    Батч: stack кадров → (N,C,H,W).
    DataLoader.

    5 Числовой пример

    (32,32,3).permute(2,0,1) → (3,32,32). Батч 64 → (64,3,32,32).

    6 Интерактив

    Permute калькулятор

    7 Код

    x = torch.from_numpy(img_hwc).permute(2,0,1).float()/255
# batch: x.unsqueeze(0) → (1,C,H,W)

    Shape после permute HWC→CHW для 32×32×3?

    8 Грабли

    • Подать (N,H,W,C) в Conv2d — получите мусор/ошибку каналов.

    9 Где в жизни

    • Интеграция OpenCV (HWC BGR) с PyTorch (CHW RGB).

    10 Проверка

    PyTorch Conv2d ждёт
    Своими словами

    Один кадр — 3 оси; батч добавляет N; порядок каналов критичен.

    11 Шпаргалка

    HWC ↔ CHW через permute. Батч (N,C,H,W). Normalize после ToTensor.

    3. Свёртка

    из лекции из семинара

    1 Зачем

    Один шаг свёртки — извлечь локальный признак (край, текстура). Стек ядер строит иерархию.

    2 Интуиция

    Наложили окно ядра → перемножили с пикселями → сложили = одна клетка карты признаков. Сдвинули окно — следующая клетка.

    3 Определение

    $$(I*K)_{ij}=\sum_{u,v} I_{i+u,j+v}\,K_{u,v}$$

    Размытие: все $1/9$. Sobel X / Y — детекторы вертикальных / горизонтальных границ.

    4 Вывод

    Одна позиция: 9 умножений + сумма для 3×3.
    Базовый «нейрон» с локальным рецептивным полем.
    Sobel: контрастные веса по краям окна → большой отклик на перепадах яркости.
    Ручные фильтры до обучения end-to-end.

    5 Числовой пример

    Патч [[1,2,3],[4,5,6],[7,8,9]] · ядро все 1/9 → среднее = 5.

    6 Интерактив

    Редактируемое ядро 3×3 + результат

    (1) Preset «blur»; (2) Sobel X/Y — края; (3) клик по карте — подсветка окна и сумма.

    ядро
    вход (клик)
    выход

    7 Код

    # NumPy один пиксель:
# s = (patch * kernel).sum()

    Среднее 1..9 при blur 1/9?

    8 Грабли

    • Перепутать корреляцию и «математическую» свёртку с flip ядра — в DL обычно correlation.

    9 Где в жизни

    • Детекция границ на сканах до нейросети — классический Sobel.

    10 Проверка

    Один шаг 3×3
    Своими словами

    Скользящее окно с весами; отклик — локальный признак.

    11 Шпаргалка

    Наложили→перемножили→сложили. Blur 1/9, Sobel — края.

    4. Kernel, stride, padding, dilation

    из семинара

    1 Зачем

    Форма карты признаков задаёт весь пайплайн до Linear. Ошибка в padding — «съехавший» размер.

    2 Интуиция

    Padding — рамка; stride — шаг окна; dilation — «дырявое» ядро (реже на старте).

    3 Определение

    $$\mathrm{out}=\left\lfloor\frac{W+2P-F}{S}\right\rfloor+1$$

    Пример: 32×32, F=3, P=1 → stride 1: 32; stride 2: 16.

    4 Вывод

    Вход расширили на P с каждой стороны → ширина W+2P.
    Same padding для F=3 → P=1.
    Окно F с шагом S: число позиций = ⌊(W+2P−F)/S⌋+1.
    Семинар: 32→32 и 32→16.

    5 Числовой пример

    ⌊(32+2−3)/1⌋+1=32; ⌊(32+2−3)/2⌋+1=16.

    6 Интерактив

    Калькулятор размера + анимация окна

    (1) Повторите 32/3/1 → 32 и stride 2 → 16; (2) P=0 — усадка; (3) смотрите бегущее окно.

    7 Код

    nn.Conv2d(3, 32, kernel_size=3, stride=1, padding=1)
# out spatial: floor((W+2P-F)/S)+1

    32, F=3, P=1, S=2 → out?

    8 Грабли

    • padding='same' в новых PyTorch ≠ всегда P=1 для любых F.

    9 Где в жизни

    • Подбор downsampling до нужного latent size под детектор.

    10 Проверка

    32×32, k=3, p=1, s=1 →
    Своими словами

    Out-size — сколько раз окно F с шагом S помещается в padded вход.

    11 Шпаргалка

    out=⌊(W+2P−F)/S⌋+1. 32,3,1 → 32 (s=1) / 16 (s=2).

    5. Несколько каналов

    из семинара

    1 Зачем

    RGB и feature maps — объёмы. Число параметров фильтра растёт с C_in.

    2 Интуиция

    Фильтр — кубик F×F×C_in; на выходе один канал; C_out таких кубиков.

    3 Определение

    $$\#\mathrm{params}=(F\cdot F\cdot C_{in}+1)\cdot C_{out}$$

    Conv2d(3,32,3) → 896; Conv2d(32,32,3) → 9248.

    4 Вывод

    Один фильтр: 3·3·3=27 + bias = 28; ×32 = 896.
    Семинар.
    Второй слой: 3·3·32+1=289; ×32=9248.
    Вопрос семинара.

    5 Числовой пример

    896 и 9248 — проверьте калькулятором ниже.

    6 Интерактив

    Калькулятор Conv2d params

    7 Код

    nn.Conv2d(3,32,3)   # 896
nn.Conv2d(32,32,3)  # 9248

    Params Conv2d(3,32,3)?

    8 Грабли

    • Забыть bias в подсчёте (−C_out).

    9 Где в жизни

    • Оценка размера модели до деплоя на мобильный сканер.

    10 Проверка

    Conv2d(32,32,3) params
    Своими словами

    Каждый выходной канал — свой фильтр по всем входам + bias.

    11 Шпаргалка

    (F²·C_in+1)·C_out. 896 и 9248 — якоря семинара.

    6. Pooling и GAP

    из лекции

    1 Зачем

    Сжать карту, увеличить поле зрения косвенно, снизить params перед Linear.

    2 Интуиция

    MaxPool — «самый сильный отклик в окне»; AvgPool — среднее. Параметров нет.

    3 Определение

    MaxPool2d(2)/AvgPool2d(2) обычно делят H,W на 2. GAP — среднее по всей карте H×W → вектор длины C.

    4 Вывод

    2×2 stride 2: (N,C,32,32)→(N,C,16,16).
    Как в SimpleVGG.
    GAP заменяет Flatten больших карт → меньше переобучения.
    Современные CNN-классификаторы.

    5 Числовой пример

    Max [[1,5],[2,3]] → 5. Params pooling = 0.

    6 Интерактив

    MaxPool 2×2 на сетке 4×4

    7 Код

    nn.MaxPool2d(2); nn.AdaptiveAvgPool2d(1)  # GAP

    Параметров у MaxPool2d?

    8 Грабли

    • Слишком агрессивный pool — теряется деталь для мелких объектов.

    9 Где в жизни

    • Сжатие feature map перед головкой классификатора документов.

    10 Проверка

    Pooling обычно
    Своими словами

    Downsample карт; GAP — экстремальный avg по пространству.

    11 Шпаргалка

    Max/Avg pool: 0 params. GAP → (N,C). 2×2 stride2 делит H,W пополам.

    7. Архитектура CNN и receptive field

    из лекции из семинара

    1 Зачем

    Нужно собрать Conv→ReLU→Pool…→Flatten→Linear и понимать, откуда 4096 входов в SimpleVGG.

    2 Интуиция

    Ранние слои — края; глубже — текстуры/части/объекты. Receptive field растёт с глубиной и pool/stride.

    3 Определение

    SimpleVGG (CIFAR 32×32): два блока Conv-Conv-Pool → 8×8×64 = 4096 → Linear.

    (N,3,32,32)после block2: (N,64,8,8)

    4 Вывод

    Pool 2×2 дважды: 32→16→8.
    Каналы 3→32→64.
    RF: каждый pool и conv расширяет «окно» на входе, видимое клеткой.
    Глубже — более глобальный контекст.

    5 Числовой пример

    8·8·64=4096. Две 3×3 вместо одной 5×5 — меньше params, тот же RF (примерно), больше нелинейностей.

    6 Интерактив

    Конструктор: форма и params после слоёв

    (1) SimpleVGG preset; (2) уберите pool — Flatten раздуется; (3) следите за RF.

    7 Код

    class SimpleVGG(nn.Module):
    def __init__(self, n_classes):
        super().__init__()
        self.block1 = nn.Sequential(
            nn.Conv2d(3,32,3,padding='same'), nn.ReLU(),
            nn.Conv2d(32,32,3,padding='same'), nn.ReLU(),
            nn.MaxPool2d(2))
        self.block2 = nn.Sequential(
            nn.Conv2d(32,64,3,padding='same'), nn.ReLU(),
            nn.Conv2d(64,64,3,padding='same'), nn.ReLU(),
            nn.MaxPool2d(2))
        self.classifier = nn.Sequential(
            nn.Flatten(), nn.Linear(8*8*64, 64), nn.ReLU(),
            nn.Linear(64, n_classes))

    Входов в Linear SimpleVGG?

    8 Грабли

    • Неверный in_features у Linear после смены числа pool.

    9 Где в жизни

    • Быстрый backbone для CIFAR-подобных задач до ResNet.

    10 Проверка

    После 2× MaxPool2d на 32×32
    Своими словами

    Стек локальных фильтров + downsample; RF — сколько входа «видит» клетка.

    11 Шпаргалка

    Conv→ReLU→Pool…. SimpleVGG: 32→8×8×64=4096. RF растёт вглубь.

    8. Переобучение CNN: аугментации, Dropout2d, BN2d

    из лекции из семинара

    1 Зачем

    CNN легко запоминают train; аугментации и регуляризация обязательны.

    2 Интуиция

    Flip/crop/jitter/rotate/cutout/шум — только train. Dropout2d гасит целые каналы. BN2d — BN по каналам карт.

    3 Определение

    Train transforms ≠ test (на test обычно Resize/CenterCrop/Normalize без random).

    4 Вывод

    Аугментации расширяют распределение train без новых лейблов.
    Не применять random на test.
    Dropout2d: маска на канал целиком — сильнее для feature maps.
    Аналог Dropout для CNN.

    5 Числовой пример

    RandomHorizontalFlip(p=0.5) — половина батча зеркалится. Test: flip нет.

    6 Интерактив

    8 Грабли

    9 Где в жизни

    9. Skip connections

    из лекции

    1 Зачем

    Глубокие сети страдают от затухания градиента; Residual = X + F(X) даёт короткий путь.

    2 Интуиция

    3 Определение

    $$\mathrm{Result}=X+F(X)$$

    ResNet — residual blocks; DenseNet — конкатенация; U-Net — skips энкодер→декoder.

    4 Вывод

    Градиент может течь напрямую по skip: ∂Result/∂X включает 1.
    Легче оптимизировать глубокие сети.
    F учит «поправку» к тождеству, а не всё отображение с нуля.
    ResNet intuition.

    5 Числовой пример

    Если F≈0 в начале, Result≈X — сигнал не затухает.

    6 Интерактив

    Слайдер «сила» F

    7 Код

    out = x + self.block(x)  # shapes must match (or proj skip)

    8 Грабли

    • Сложение при разных shape каналов без 1×1 proj.

    9 Где в жизни

    • ResNet18/50 — дефолтный backbone в CV-проде.

    10 Проверка

    Residual блок
    Своими словами

    Короткий путь для градиента и тождественный baseline.

    11 Шпаргалка

    X+F(X). ResNet / DenseNet / U-Net — разные виды связей.

    11. Transfer learning (VGG16)

    из семинара

    1 Зачем

    Мало своих картинок — берём features с ImageNet, учим голову.

    2 Интуиция

    VGG16: features + classifier. После features на 224×224 → 512×7×7 = 25088 входов в FC.

    3 Определение

    Заменить последний Linear; заморозка requires_grad=False; проверить, что grad не течёт.

    512·7·7=25088

    4 Вывод

    Почему 25088 при CIFAR 32×32? Предобучение на 224; для 32 нужны другие головы/адаптация (семинар поясняет).
    Не путать вход ImageNet и CIFAR.
    Проверка заморозки: все p.requires_grad False у features; opt только на classifier.
    Иначе «случайно» дообучите весь VGG.

    5 Числовой пример

    512×7×7=25088.

    6 Интерактив

    Заморозка — счётчик trainable

    7 Код

    model = torchvision.models.vgg16(weights="DEFAULT")
for p in model.features.parameters():
    p.requires_grad = False
model.classifier[6] = nn.Linear(4096, n_classes)
# проверить: [p.requires_grad for p in model.features.parameters()]

    512×7×7 = ?

    8 Грабли

    • Забыли eval/freeze BN в features при partial freeze (модуль 4 углубит).

    9 Где в жизни

    • Классификация редких типов документов на ImageNet-backbone.

    10 Проверка

    25088 это
    Своими словами

    Переиспользуем визуальные признаки; учим новую голову под свою задачу.

    11 Шпаргалка

    features+classifier; 25088; freeze requires_grad=False; заменить последний Linear.
