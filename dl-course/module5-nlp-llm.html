    1. Как представить текст числами: мешок слов

    из лекции

    1 Зачем

    Таблицы — числа, картинки — пиксели. Текст нужно сначала превратить в векторы. Простейший способ — мешок слов (bag of words, BoW): считаем, сколько раз каждое слово словаря встретилось, порядок забываем.

    2 Интуиция

    Три предложения из лекции:

    1. «Мой дорогой, добрый мой друг – это очень дорогой подарок»
    2. «Это мой пес, очень дорогой мой друг»
    3. «Добрый друг – дорогой подарок»
    мойдорогойдобрыйдругэтооченьподарокспасибопес
    Текст 1221111100
    Текст 2210111001
    Текст 3011100100

    3 Определение

    Словарь $V=\{w_1,\dots,w_{|V|}\}$. Документ $d$ → вектор $x\in\mathbb{R}^{|V|}$, $x_i=\mathrm{count}(w_i,d)$. Ограничения: нет порядка, омонимы совпадают, редкие информативные слова тонут в частых («и», «это»).

    TF-IDF (кратко): $\mathrm{tfidf}(t,d)=\mathrm{tf}(t,d)\cdot\log\frac{N}{\mathrm{df}(t)}$ — поднимает редкие по корпусу термины.

    документ → x: (|V|,) словарь V похожесть: cosine(x,y)

    4 По шагам

    1. Токенизировать (здесь — слова в нижнем регистре без пунктуации).
    Единый словарь.
    2. Построить $V$ по корпусу; для каждого документа — счётчик.
    Размерность = |V|.
    3. (Опц.) TF-IDF вместо сырых счётчиков.
    Меньше вес стоп-слов.

    5 Числовой пример

    Текст 1: «мой»=2, «дорогой»=2. Cosine(текст1, текст2) посчитайте в виджете ниже.

    Cosine между текстами лекции

    2. Эмбеддинги и word2vec

    из лекции сверх курса

    1 Зачем

    BoW кодирует документ, но не «смысл слова». Эмбеддинг — вектор слова такой, что похожие слова близки в пространстве.

    2 Интуиция

    Как координаты города: широта/долгота. На карте лекции оси — положительность и устарелость: «радость» на СВ, «астрофизика» на севере, древние слова южнее.

    Арифметика смыслов: $\overrightarrow{\text{king}}-\overrightarrow{\text{man}}+\overrightarrow{\text{woman}}\approx\overrightarrow{\text{queen}}$.

    3 Определение

    Косинусная близость: $\displaystyle\cos(u,v)=\frac{u\cdot v}{\|u\|\|v\|}$.

    word2vec учит эмбеддинги, предсказывая контекст:

    • CBOW: по контексту $c$ предсказать центральное слово $w$: $P(w\mid c)=\mathrm{softmax}(v_w^\top h_c)$.
    • Skip-gram: по центру $w$ предсказать слова контекста: $P(c\mid w)=\mathrm{softmax}(v_c^\top v_w)$.

    Loss skip-gram (один контекст): $\mathcal{L}=-\log\frac{\exp(v_c^\top v_w)}{\sum_{u\in V}\exp(v_u^\top v_w)}$ — обычная CE по словарю.

    На практике — negative sampling: $\mathcal{L}=-\log\sigma(v_c^\top v_w)-\sum_{n\in Neg}\log\sigma(-v_n^\top v_w)$.

    E: (|V|, d) слово → строка E cos ∈ [−1,1]

    4 Вывод loss по шагам

    1. Skip-gram: хотим $P(c\mid w)$ высоким для настоящих пар (w, c).
    «Слова рядом — похожи».
    2. Score = скалярное произведение эмбеддингов $v_c^\top v_w$. Softmax по всем словам словаря.
    Как линейный классификатор (модуль 1).
    3. CE: $-\log P(c\mid w)$. Полный softmax дорог → negative sampling / hierarchical softmax.
    Связь с модулем 0: низкий ранг / эффективность.

    5 Числовой пример

    $u=(1,0)$, $v=(0.6,0.8)$: $\|v\|=1$, $\cos=0.6$.

    Клик по слову — соседи по cosine. Арифметика: A − B + C.

    3. Токенизация и BPE

    из лекции сверх курса

    1 Зачем

    Слова: огромный словарь, OOV. Символы: слишком длинные последовательности. BPE (Byte Pair Encoding) — компромисс: частые куски сливаются в токены.

    2 Интуиция

    Как сжатие: частое «th» становится одним символом. В LLM то же — «ing», «##tion», куски имён.

    3 Определение

    1. Инициализация: словарь = все символы корпуса.
    2. Подсчёт пар: частоты соседних токенов.
    3. Слияние: самая частая пара → новый токен.
    4. Повтор шагов 2–3 заданное число раз (или до размера словаря).

    4 По шагам на примере

    1. Текст: low low low low lower newest newest → символы + маркер конца слова.
    Учебный пример BPE.
    2. Частая пара, напр. e+w / l+o — зависит от подсчёта; сливаем топ.
    Жадный алгоритм.
    3. После нескольких merge словарь содержит куски вроде low, est.
    Баланс длины и покрытия.

    BPE по шагам

    from collections import Counter
def get_stats(words):  # words: list[list[str]]
    pairs = Counter()
    for w in words:
        for i in range(len(w)-1):
            pairs[(w[i], w[i+1])] += 1
    return pairs
def merge(words, pair):
    a,b = pair; out=[]
    for w in words:
        i=0; nw=[]
        while i < len(w):
            if i < len(w)-1 and w[i]==a and w[i+1]==b:
                nw.append(a+b); i+=2
            else: nw.append(w[i]); i+=1
        out.append(nw)
    return out

    4. Контекст и attention

    из лекции сверх курса

    1 Зачем

    Один токен — один эмбеддинг. Омонимы («банк» река/финансы) без контекста неразличимы. Сеть насыщает эмбеддинг соседями через Attention.

    2 Интуиция

    Каждый токен спрашивает: «на кого мне смотреть?» (Query), предлагает «кто я» (Key), отдаёт содержимое (Value). Взвешенная сумма Value — новый вектор.

    3 Определение

    $$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

    $Q,K,V\in\mathbb{R}^{n\times d_k}$ (для self-attention из одних и тех же $X$ линейными проекциями). Деление на $\sqrt{d_k}$ стабилизирует softmax.

    Позиционные эмбеддинги: к токену добавляют вектор позиции (sin/cos или learned) — иначе attention перестановочно-инвариантен.

    Блок трансформера (обзор): Multi-Head Self-Attention → Add&Norm → FFN → Add&Norm (и снова).

    X: (n, d) W_Q,W_K,W_V A: (n, n) веса внимания

    4 Self-attention на числах

    1. Три токена, d=2: $x_1=(1,0),\;x_2=(0,1),\;x_3=(1,1)$. Пусть $Q=K=V=X$ (без проекций).
    Упрощение для ручного счёта.
    2. Scores $=QK^\top/\sqrt{2}$. Softmax по строкам → веса.
    Каждая строка — распределение «куда смотреть».
    3. Выход = веса · V. Токен «впитал» соседей.
    Насыщение контекстом из лекции.

    5–6 Интерактив: матрица внимания

    Self-attention для короткого предложения

    Меняйте scale / температуру softmax. Клик по слову подсвечивает строку внимания.

    7 Код

    import numpy as np
def attention(Q, K, V):
    d = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d)
    scores -= scores.max(axis=-1, keepdims=True)
    A = np.exp(scores); A /= A.sum(axis=-1, keepdims=True)
    return A @ V, A

    • Softmax без −max → численное переполнение.

    5. Как работает GPT

    из лекции сверх курса

    1 Зачем

    GPT решает задачу: предсказать следующий токен по всем предыдущим (вариант 2 из лекции).

    2 Интуиция

    Авторегрессия: сгенерировали токен → добавили в контекст → снова предсказали. Как дописывание текста по одной букве/токену.

    3 Определение

    Алгоритм обучения (лекция):

    1. Собрать тексты → BPE → случайные эмбеддинги.
    2. Подать последовательность; эмбеддинги насыщаются контекстом (causal attention).
    3. На каждом шаге предсказать следующий токен; CE loss; обновить веса.

    Маскирование будущего: в матрице внимания позиция $i$ видит только $j\le i$ (иначе train «списывает» ответ).

    Логиты $z$, температура $T$: $p_i=\mathrm{softmax}(z_i/T)$. $T\to0$ — argmax; $T$ велика — почти равномерно.

    Top-k: оставить k наибольших логитов, остальные −∞. Top-p (nucleus): наименьшее множество, чья сумма вероятностей ≥ p.

    4 По шагам генерации

    1. Контекст → модель → логиты по словарю.
    Один forward.
    2. /T → (opt.) top-k / top-p → softmax → sample или argmax.
    Контроль «креативности».
    3. Токен append → повтор до EOS / лимита.
    Авторегрессия.

    Крутите temperature, top-k, top-p — смотрите массу вероятности.

    7 Код (минимальная LM)

    class TinyLM(nn.Module):
    def __init__(self, V, d, n_layers=2):
        super().__init__()
        self.emb = nn.Embedding(V, d)
        self.pos = nn.Embedding(512, d)
        layer = nn.TransformerEncoderLayer(d, nhead=4, batch_first=True)
        self.tr = nn.TransformerEncoder(layer, n_layers)
        self.head = nn.Linear(d, V)
    def forward(self, idx):
        B, T = idx.shape
        x = self.emb(idx) + self.pos(torch.arange(T, device=idx.device))
        # causal mask: -inf выше диагонали
        mask = nn.Transformer.generate_square_subsequent_mask(T).to(idx.device)
        h = self.tr(x, mask=mask)
        return self.head(h)  # (B,T,V)

    6. Адаптация LLM

    из лекции сверх курса

    1 Зачем

    Базовая модель знает «язык вообще». Нужны свои данные, актуальность, стиль, безопасность — без обучения с нуля за миллионы.

    2 Своя vs внешняя

    Своя LLMВнешняя LLM
    Плюсыбезопасность данных, контроль, развитие своих технологийбыстрый старт, много задач «из коробки»
    Минусывысокая стоимость разработкиутечки/зависимости, лимиты API

    3 Методы

    Дообучение (FT): продолжить CE next-token на своих текстах / инструкциях — долго и дорого на полной модели.

    Эффективное FT / LoRA: заморозить W, учить низкоранговую добавку $\Delta W=BA$, $B\in\mathbb{R}^{d\times r}$, $A\in\mathbb{R}^{r\times k}$, $r\ll\min(d,k)$. Связь с модулем 0: SVD / низкий ранг — мало параметров несут адаптацию.

    $$W'=W+\frac{\alpha}{r}BA\quad(W\text{ frozen})$$

    RAG: запрос → поиск релевантных документов → ответ модели по знаниям + документам (актуальность без переобучения).

    RLHF: модель оценки реакции (reward) → дообучение политики на награду (предпочтения людей).

    4 Когда что выбирать

    СитуацияЧто брать
    Нужны свежие факты / база знанийRAG
    Свой стиль / доменный язык, мало GPULoRA / adapters
    Много данных и железа, смена поведенияполное FT
    Выравнивание «как отвечать людям»RLHF / предпочтения
    Секретные данные нельзя в APIсвоя / on-prem модель
    Прототип за деньвнешняя LLM + промпты (± RAG)

    Лекция: RAG — простой в запуске; полное FT — ресурсы; RLHF — дорогостоящий процесс под задачу.
